# Idea Research: Manacá-Instruct-PT — Instruction-Tuned Version of the Manacá-1B Base Model

- **Slug**: manaca-instruct-pt
- **Created**: 2026-09-14
- **Evidence confidence (overall)**: medium — strong sourcing on prior art and hardware feasibility; low/no sourcing on demand signal and dataset licensing specifics.

## Users & Demand

- No support tickets, interviews, or usage data exist for this idea — it is a self-initiated project with no external demand signal recorded anywhere in the source documents or found during research. — ASSUMPTION (confidence: low)
- General market signal: the academic literature explicitly frames Brazilian Portuguese as "under-served by open language models," which is the stated motivation for Manacá-1B itself. — [source: arxiv.org/abs/2608.30114] (confidence: medium)
- The Manacá-1B paper's own authors state they "plan to train and evaluate an instruction-tuned version of Manacá" — i.e., there is a real, named, credentialed team with stated intent to build essentially the same thing this idea proposes, as official future work. — [source: arxiv.org/abs/2608.30114] (confidence: high)

## Prior Art

- **Official Manacá roadmap**: the Manacá-1B paper/repo explicitly scopes itself to the base model and defers instruction-tuning to future work by the original authors. This confirms the intake note's framing ("instruction tuning is not part of the base model") is accurate, and that this project's core idea is directionally aligned with — but may eventually be duplicated by — the official team's own plans. — [source: github.com/Instituto-IA-LNCC/manaca-1b-base, arxiv.org/abs/2608.30114] (confidence: high)
- **manaca-lab** (`github.com/lucaslmfbib/manaca-lab`): an existing early-stage (7 commits) community project building an experimental Streamlit/notebook interface for exploring the Manacá-1B **base** model, focused on AI/information-science/legal use cases. It does **not** do fine-tuning, QLoRA, or instruction-dataset work — it is inference/exploration only, with RAG and PDF integration still on its unimplemented roadmap. This is adjacent prior art (same base model, same country/community) but does not overlap with the fine-tuning objective. — [source: github.com/lucaslmfbib/manaca-lab] (confidence: high)
- **Tucano2 family** (Polygl0t, on Hugging Face): a directly competing, already-shipped alternative — open-source Portuguese LLMs from 0.5B to 3.7B parameters, with **instruction-tuned variants already released** (SFT + Anchored Preference Optimization), supporting RAG, function calling, tool use, summarization, and structured output. The 3.7B Instruct variant reportedly beats Qwen3-4B and SmolLM3-3B on Portuguese knowledge/reasoning benchmarks. This is materially more mature than what this idea proposes to build from scratch, in a similar or smaller parameter range. — [source: huggingface.co/blog/Polygl0t/tucano2, huggingface.co/collections/Polygl0t/tucano2] (confidence: high)
- **Older PT-BR instruction-tuned model lineage** (context, not direct competitors to a 1.7B model): Sabiá (7B/65B, Llama-based), Bode (LoRA-tuned Llama 2 + translated Alpaca), Gervásio (fine-tuned Llama 2 7B, BR/EU variants), Cabrita (OpenLLaMA 3B). These establish that "translate Alpaca-style instructions to PT-BR + LoRA fine-tune a base model" is a well-trodden, low-novelty technique in this space, not a new method. — [source: sciencedirect.com/science/article/pii/S2666827024000343, researchgate.net/publication/374641537, arxiv.org/pdf/2401.02909, arxiv.org/pdf/2402.18766] (confidence: medium)

## Market & Context

- Cost of doing nothing: users needing a small, local, PT-BR instruction-following model already have a working, more mature alternative today (Tucano2-qwen, various sizes including sub-1B and ~1.5B/3.7B, already instruction-tuned and benchmarked) — so "nothing happens" does not leave a PT-BR capability gap at this model scale; it only leaves *this specific author* without a from-scratch learning experience. — [source: huggingface.co/collections/Polygl0t/tucano2] (confidence: medium)
- Alternative users cope with today: machine-translated Alpaca/Dolly-style PT-BR instruction datasets are freely available on Hugging Face (e.g. `dominguesm/alpaca-data-pt-br`, Canarim Instruct Dataset with 300k+ instructions, translated Dolly/OASST/HH-RLHF blends), meaning the "build a 100–300 example dataset from scratch" step in the project plan duplicates existing, larger, ready-to-use resources that could instead be adapted/curated rather than authored from zero. — [source: huggingface.co/datasets/dominguesm/alpaca-data-pt-br, github.com/gustrd/cabra] (confidence: medium)

## Data & Constraints

- Base model specs (confirmed): Manacá-1B-base is 1,722,951,680 parameters, 24 layers, 4096-token context, SentencePiece 64k-vocab tokenizer, CC BY 4.0 licensed, trained on ~20.1B PT-BR tokens (GigaVerbo/Ulysses Tesemõ/Wikipedia-pt). Benchmarks: CALAME-PT 60.63%, LAMBADA-PT 45.31% (strongest sub-7B model on this metric), HellaSwag-PT 41.61%, ARC-Challenge-PT 27.18% (near chance). The near-chance ARC-Challenge score signals weak reasoning ability in the base model, which is a real ceiling on how well any instruction-tuned derivative can perform on reasoning-heavy tasks (e.g., document Q&A, classification with nuance). — [source: github.com/Instituto-IA-LNCC/manaca-1b-base] (confidence: high)
- Hardware — RTX 5050 8GB VRAM for QLoRA: a controlled profiling study fine-tuning Qwen2.5-1.5B-Instruct with LoRA/QLoRA on an RTX 4060 (also 8GB VRAM) found it feasible with batch sizes up to 2 and sequence lengths up to 2048 tokens. Manacá-1B (1.7B params, 4096 context) is closely comparable in scale, so the project's core hardware assumption (§4, §15–16 of the project doc) is well-supported by independent evidence, not just internal optimism. — [source: arxiv.org/html/2509.12229v1] (confidence: high)
- Hardware — Dell G3 / GTX 1050 for GGUF deployment: retail Dell G3 15 configurations of this generation (i5-8300H era) most commonly shipped with the GTX 1050 **4GB VRAM** variant, not 2GB — better GPU-offload headroom for a ~1GB (Q4_K_M, ~1.7B params) GGUF file than a worst-case 2GB assumption; exact VRAM on the specific unit is still unconfirmed. No GTX 1050-specific llama.cpp tokens/sec benchmark was found — general guidance suggests small (~1-2B) Q4_K_M models run comfortably even CPU-only at these RAM levels (32GB), so this is very likely not a real blocker either way, but is unverified for this exact card. — [source: amazon.com listing for Dell G3579-5965BLK-PUS, walmart.com listing] (confidence: medium)
- License: CC BY 4.0 on the base model permits derivative fine-tuned models with attribution — no licensing blocker identified for the core idea. — [source: github.com/Instituto-IA-LNCC/manaca-1b-base] (confidence: medium)

## Evidence Against the Idea

- **Duplication risk with the model's own creators**: the Manacá-1B authors have explicitly stated instruction-tuning Manacá is their own planned future work. If/when they release an official Manacá-Instruct, this project's output is redundant with an authoritative version likely trained with more data, compute, and domain expertise. — [source: arxiv.org/abs/2608.30114] (confidence: high)
- **A more mature, already-released alternative exists at a similar/better scale**: Tucano2-qwen already ships instruction-tuned PT-BR models from 0.5B–3.7B with SFT+APO, RAG support, tool use, and published benchmarks beating larger competitors. Anyone who needs "a small local PT-BR instruction-following model" today already has a better-tested option than what this project would produce as a first iteration. This substantially weakens the "relevance" case if the goal is to fill a real capability gap rather than to learn. — [source: huggingface.co/blog/Polygl0t/tucano2] (confidence: high)
- **Weak base-model reasoning ceiling**: near-chance ARC-Challenge-PT (27.18%) on the base model suggests instruction-tuning may struggle to produce strong performance on tasks that need more than surface-level pattern completion (e.g., nuanced classification, document Q&A / RAG answer synthesis planned for later phases) — the project's own ambitions (§1: "responder perguntas sobre documentos") may exceed what this base model can support well, independent of fine-tuning quality. — [source: github.com/Instituto-IA-LNCC/manaca-1b-base] (confidence: medium)
- **No external demand signal**: nothing in the intake or this research surfaced a user, team, or business need being served — the project's own text repeatedly frames the payoff in portfolio/learning terms ("ótima para demonstração de portfólio"), not user-need terms. If the goal is "build something people need," the evidence doesn't support that; if the goal is "learn the full LLM specialization lifecycle hands-on," the evidence doesn't contradict that. — ASSUMPTION (confidence: low, since origin/trigger is itself unresolved per intake's `[NEEDS CLARIFICATION]`)
- **Dataset-from-scratch is redundant work**: existing PT-BR instruction datasets (translated Alpaca, Canarim 300k+, Dolly/OASST blends) already cover the exact task categories this project lists (grammar correction, rewriting, summarization) at far larger scale than the 100–300 examples the roadmap targets, meaning the "build our own dataset" step recreates existing public assets rather than filling a gap. — [source: huggingface.co/datasets/dominguesm/alpaca-data-pt-br, github.com/gustrd/cabra] (confidence: medium)

## Gaps & Open Questions

- [NEEDS CLARIFICATION: Is the project's goal explicitly personal learning/portfolio value, or does the author intend this to serve real users/downstream consumers? This is the single biggest factor for judging "relevance" — the evidence supports the idea strongly under a learning framing and weakly under a "fill a market/capability gap" framing, since Tucano2 already fills that gap at a comparable or better scale.]
- [NEEDS CLARIFICATION: Does the author want to reuse/adapt an existing PT-BR instruction dataset (faster, larger, proven) or is hand-authoring a small dataset itself part of the learning objective? The roadmap document assumes the latter without discussing the former as an option.]
- [NEEDS CLARIFICATION: What VRAM does the specific Dell G3 unit's GTX 1050 actually have (2GB vs 4GB) — determines whether GPU offload is viable at all on that machine or whether the deployment phase is CPU-only by necessity.]
- [NEEDS CLARIFICATION: Has the author checked whether Manacá-1B's own team has published (or has a timeline for) an official instruct version since the August 2026 paper? A near-term official release would significantly change the calculus for continuing independent work on the same base model.]
- [NEEDS CLARIFICATION: No PoETa-v2 or Manacá-specific instruction-following benchmark numbers were found for any DIY QLoRA attempt at this scale — there's no third-party evidence (beyond the general Qwen2.5-1.5B profiling study) that QLoRA specifically on the Manacá tokenizer/architecture behaves well; the project doc's own §12 baseline step is the first real test of this.]
