## Verdict & Rationale

**Go.** Every criterion clears the `adequate` bar required for a go verdict, feasibility is `strong`, and a concept option (B — Core Lifecycle v1) was both recommended with cited rationale and explicitly confirmed by the author. The idea is not being waved through on enthusiasm: research.md actively surfaced the strongest case against it (a more mature alternative — Tucano2 — already exists, and the official Manacá team has stated intent to ship their own instruct version), and problem.md and concept.md directly confront that evidence rather than ignore it, concluding that the project's confirmed dual goal (learning + a public artifact the author stands behind) survives that competition on its own terms rather than needing to "win" against Tucano2. The two remaining open items (dataset choice, target hardware for the usability metric) are ordinary specification-stage decisions, not blockers to starting specification.

## If go — Handoff to `/speckit-specify`

- **Problem**: The author wants hands-on, end-to-end experience with the full LLM specialization lifecycle (dataset, SFT, QLoRA, evaluation, quantization, deployment) and, from that work, a genuinely usable PT-BR instruction-following model — built from the Manacá-1B base model and published publicly on Hugging Face — where today only the untuned base model exists.
- **Chosen approach**: Concept Option B — Core Lifecycle v1. Baseline run on the untuned base model → adapt/curate one or more existing PT-BR instruction dataset(s) (not hand-authored from scratch) covering grammar correction, rewriting, summarization, simplification, and classification → QLoRA fine-tuning on the RTX 5050 (8GB VRAM) → full evaluation against a fixed prompt set, covering both new-capability gains (Grupo A) and catastrophic-forgetting checks (Grupo B, per project doc §30) → at most one iteration round → merge adapter → GGUF quantization (Q4_K_M plus at least one comparison level) → real, measured benchmark run on the Dell G3 (GTX 1050, 4GB VRAM, 32GB RAM) → publish to Hugging Face with a model card disclosing the personal/learning framing, attribution to the CC BY 4.0 base model, and documented limitations.
- **In scope**: Everything listed under Concept Option B's sketch above, including both machines and a public Hugging Face release.
- **Out of scope**: Any API (FastAPI or otherwise), web/CLI interface, or RAG/document-Q&A layer; multiple task-specialized LoRA adapters; matching or beating Tucano2/other mature alternatives on raw benchmark quality; reproducing the official Manacá pretraining pipeline; ongoing support/maintenance commitments to public downloaders after release.
- **Success metrics**: Measurable Base-vs-Instruct improvement on the fixed eval set across all five task categories; minimal catastrophic forgetting on Grupo B tasks; the model runs "sem gargalos" (reliable, stall-free generation) at approximately 70 tokens/second — **target hardware/quantization level still to be pinned down in `/speckit-specify`**; successful, measured GGUF deployment on the Dell G3; a published Hugging Face model with adequate documentation; every pipeline stage actually executed and documented at least once (the learning-completeness signal, independent of final model quality).
